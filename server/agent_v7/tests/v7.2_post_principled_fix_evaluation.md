## Key Improvement: DISCOVER → PLAN → EXECUTE Protocol

Added to prompts_v2.py:

```
Discovery tools (list_sessions, search_sessions) are like getting a MAP - they show you WHERE to look.
Detail tools (get_7c_analysis, get_transcript, etc.) are like VISITING - they give you actual evidence.

After calling ANY discovery tool:
1. DISCOVER: Call list_sessions or search_sessions to find relevant sessions
2. PLAN: State which sessions need detailed analysis
3. EXECUTE: Make each planned tool call
4. SYNTHESIZE: Only respond after ALL planned calls complete
```

**Impact**: This protocol teaches the LLM the correct mental model for tool usage, rather than using reactive guardrails to override incorrect behavior.

## What Made the Difference

### 1. DISCOVER → PLAN → EXECUTE Protocol (Critical)

The protocol shifted the LLM's mental model:
- **Before**: list_sessions returns data → I have evidence → respond
- **After**: list_sessions returns a MAP → I now know WHERE to look → retrieve details → respond

This is a **teaching** approach rather than a **guarding** approach.

### 2. Extended Superlative Patterns

Added patterns for implicit superlatives:
```python
r'which\s+(?:session|discussion)\s+had\s+more',      # "Which session had more X"
r'which\s+(?:session|discussion)\s+had\s+(?:better|worse)',  # "Which session had better/worse X"
r'across\s+(?:all\s+)?sessions',                     # "7C scores across sessions"
```

These patterns trigger the `min_sessions_needed=2` requirement even without explicit session names.

### 3. Removed Pattern Duplication

Removed `r'across\s+(?:all\s+)?sessions'` from THEMATIC_PATTERNS to ensure it's classified as SUPERLATIVE (which requires multi-session retrieval).

### 4. Retrieval Intent Detection

Added more phrases to catch the "Please hold on" bug:
```python
"proceed with retrieving", "let me proceed", "i'll now call",
"i will now call", "let me now call", "let's start by retrieving"
```

## Architecture Assessment

### Principled Approach Benefits

1. **Teachable**: The DISCOVER → PLAN → EXECUTE protocol can be understood and followed by the LLM
2. **Generalizable**: Same prompt works for any query type requiring multi-entity data
3. **Modular**: Pattern constants can be extended without changing core logic
4. **Maintainable**: Clear separation between classification, routing, and execution

### Why This Works

The key insight is that **LLMs optimize locally** (respond as soon as evidence exists) rather than **globally** (ensure all required evidence before responding). The protocol addresses this by:

1. Explicitly labeling discovery tools as "maps, not evidence"
2. Requiring an explicit PLAN step before execution
3. Using completeness gating as a safety net, not the primary mechanism
